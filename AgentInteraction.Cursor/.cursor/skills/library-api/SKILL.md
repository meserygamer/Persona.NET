# Библиотечный API

Сигнатура, FQN, XML и список членов — из `**/type-catalog/*.md`. Тело и исходящие ссылки — `find`. Потребители — `usedBy`. Подстрока в исходнике, когда FQN ещё неизвестен — `textSearch`. Семантический поиск по смыслу — `ragSearch`. Исходники библиотеки на диске не ищутся и не додумываются.

Перед первым `find`, `usedBy`, `textSearch` или `ragSearch` прочитай [mcp-contract.md](mcp-contract.md). Разборы типовых ошибок — [examples.md](examples.md).

## Как найти сервер

Имя namespace в runtime часто длиннее, чем `libraries-info`.

1. `GetDynamicTools` без аргументов.
2. Если сервера нет в списке — `GetDynamicTools` с `pattern: "libraries-info"`.
3. Возьми точные `namespace` и `toolName` из ответа. Схему параметров — отдельным вызовом `GetDynamicTools` с этим namespace и `toolName`.
4. `namespaceStatus: "needsAuth"` — `mcp_auth` для этого namespace, затем повтори вызов.
5. Ошибка «tool/namespace not found» с первого раза — повод сверить имя. Tools называются `find`, `usedBy`, `textSearch` и `ragSearch`. `find`, `usedBy` и `textSearch` есть всегда. `ragSearch` публикуется, только если на сервере включён семантический поиск: если остальные tools `libraries-info` видны, а `ragSearch` нет — RAG выключен. Тогда ищи по смыслу через `textSearch` с вероятными идентификаторами и каталог; сам tool не ищи.

## Какой источник

| Вопрос | Куда идти |
|---|---|
| Что это, сигнатура, XML, список членов | Каталог: Grep, затем узкий Read |
| Тело, реализация, исходящие ссылки | `find` с FQN из каталога и узким `memberNames`, если нужен один член |
| Кто вызывает метод или читает член | `usedBy` с именем этого члена |
| Кто создаёт экземпляр | Несколько запросов, см. ниже |
| Где в исходнике встречается строка, FQN ещё неизвестен | `textSearch`, затем каталог по `Type` из совпадения, затем `find` |
| Где в коде по смыслу, без точной подстроки | `ragSearch`, затем каталог по `Type`, затем `find` |

`find` не вызывай, чтобы узнать сигнатуру или XML. `usedBy` не пристёгивай к каждому `find`. `textSearch` не вызывай, если строка `FQN:` и нужный член уже есть в каталоге: тело этого члена берётся через `find`. `textSearch` читает текст объявлений в индексе, а не markdown каталога. `ragSearch` не заменяет `textSearch` для известных литералов.

Большой тип целиком ради одного члена не запрашивай: передай имя члена. Пустой `memberNames` у `usedBy` отвечает на другой вопрос — где тип стоит в сигнатурах, полях и базах. Это не список создателей и не список вызовов метода. Числа `UsedByTotal` на этих двух уровнях часто расходятся; смешивать их нельзя.

## Кто создаёт экземпляр

1. В каталоге найди строку конструктора (`` `public Store()` ``) и вызови `usedBy` с `memberNames` из короткого имени типа (`Store`). Не `.ctor` и не пустой список.
2. Фабрики, десериализация, `Activator.CreateInstance` и приведения ищи отдельно: `find` по подозрительным потребителям из шага 1 или `usedBy` по уже известному из каталога методу-фабрике.
3. Несколько перегрузок — в `usedBy` смотри `Signature` у элементов `Members` с одним `Name`; детали вызова уточняй через `find` в коде потребителя.

## Исследование

1. Назови вопрос одной фразой: сигнатура, поведение, кто вызывает, кто создаёт, где лежит строка.
2. Выбери одну строку таблицы выше.
3. Для `find` и `usedBy` подтверди в каталоге строку `FQN:` и, если нужен член, строку этого члена в блоке того же типа. Нет строки `FQN:` — остановись и так и скажи. Эти два tool не вызывай. `textSearch` эту строку до вызова не требует.
4. Вызови один нужный tool. Параметры и разбор ответа — в [mcp-contract.md](mcp-contract.md).
5. `Error` передай пользователю. Пустой `Matches` у `find` после сверки FQN — пары нет в индексе. У `usedBy` см. контракт: три формы пустого ответа; `UsedBy: []` у объявленного члена — граница статического анализа, не обязательно отсутствие вызовов. Пустой `Matches` у `textSearch` при `Error` = null — подстрока не найдена. Пустой `Matches` у `ragSearch` при `Error` = null — близких фрагментов нет. `Error` про таймаут или отмену — повтори тот же вызов один раз. `Error` `ragSearch` об отсутствующем или несовместимом векторном индексе — семантический поиск недоступен, продолжай через `textSearch` и каталог. `UsedByTotal` или `Total` больше длины списка — выборка обрезана.
6. В ответе приведи из каталога сигнатуру, `FQN`, `Type params`, `Base`, `Implements`, `Attributes` (если есть) и XML. Тело цитируй, только если вопрос был про поведение. Сниппет `textSearch` и `Source` из `ragSearch` телом метода не являются: для тела нужен `find`. `ChunkIndex` читай только при `includeFragmentSource: true`. Явная реализация интерфейса — не обычная перегрузка того же идентификатора.

## Код с той же сигнатурой

1. Возьми файл каталога с тем `targetFramework`, под который собирается проект. Снимки разных TFM не взаимозаменяемы.
2. Для каждого типа и члена, который собираешься вызвать, найди строку `FQN:` и строку члена. Короткое нерезолвленное имя не заменяй угаданным FQN.
3. Прочитай `Obsolete` на типе и члене. Если атрибут называет замену, подтверди замену отдельной строкой каталога и вызывай её.
4. Если от вызова зависят `null`, исключения или побочные эффекты — прочитай тело через `find` с именем этого члена.
5. Возьми несколько реальных вызовов: `usedBy` с тем же `memberNames` и `limit` по умолчанию. Смотри потребителей того же TFM и `Signature` перегрузок. Для оператора в `usedBy` подойдут `operator …` или `op_*` из контракта.
6. Пиши вызов в этой сигнатуре и в этом паттерне аргументов.
7. Широко используемый тип (соединение, сущность, менеджер схем) с пустым `memberNames` не запрашивай: сузь до члена, который реально вызываешь.
